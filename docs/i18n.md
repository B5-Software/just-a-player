# Language support

The shared setting `language` accepts `system` (default), `zh-CN` and `en`.
Chinese system locales resolve to Simplified Chinese; all other unsupported locales resolve to English.
Desktop uses the OS preference exposed by Electron, Android uses its configuration locale, and standalone native mode uses `sys-locale`.
The setting persists across full/native switches. It does not restart audio.

`apps/desktop/src/shared/locales/en.json` is the shared source-key catalogue for React, desktop integration and Rust/egui.
Chinese source keys remain stable; translated labels must never become IDs, paths, preset keys or IPC values.
Use numbered placeholders (`{0}`, `{1}`) for parameters. More specific templates take precedence over generic templates; parameters are inserted without translation.

React components subscribe with `useLocale()` and pass their presentation tree through `ui(...)` during render.
This translates text and accessible labels without observing or modifying the DOM. Explicit `t(...)` calls cover canvas text, format descriptions and labels inside parameters.
Mark metadata and filenames with `translate="no"`; lyric glyph rendering intentionally bypasses UI translation.
Do not pass song titles, lyrics, imported names or stable identifiers through `t`.

Native UI uses `jap_light::i18n::tr` for literal labels and `tr_text` for dynamic report text.
Call `configure` with the current shared settings before drawing a surface, including the tray.
Keep icon behavior based on IDs, rather than translated labels.

Validation:

```sh
pnpm typecheck
cargo test -p jap-light i18n --lib
node apps/desktop/scripts/e2e-i18n.mjs
```

The end-to-end check uses an unsupported system locale, changes language while playing, preserves a Chinese track title, visits panels and opens the English file browser.
README language variants are [简体中文](../README.md) and [English](../README.en.md).
